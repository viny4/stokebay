# Decisions

One line per decision: date, decision, reason.

- 2026-10-19 — The app lives at the repo root, not in a `project-hud/` subfolder. — Keeps paths and scripts simple; the repo is the app.
- 2026-10-19 — `projects.status` is user-set only; "cold" is derived from `last_activity_at`. — Auto-pausing silently overrides user intent and produces pauses with no `where_i_stopped`, which defeats the resume card.
- 2026-10-19 — IDs are text ULIDs. — Integer IDs collide when merging data across devices (export/import, future sync).
- 2026-10-19 — Timestamps are UTC epoch milliseconds (integer). — One format avoids timezone and parsing bugs in timelines and inactivity maths.
- 2026-10-19 — Activity events are never updated, but are deleted with their project. — "Users own their data" requires that deleting a project removes its history.
- 2026-10-19 — Daily SQLite backup, keep last 7. — Local-first means a single corrupted file is otherwise total data loss.
- 2026-10-19 — No per-repo Git file watchers; refresh on window focus, project open and a slow sweep. — Hundreds of watchers hit inotify limits on Linux; this keeps cross-platform behaviour consistent.
- 2026-10-19 — MiniSearch deferred; FTS5 prefix queries handle type-ahead. — Avoids keeping two indexes in sync; revisit only if benchmarks show FTS5 is too slow.
- 2026-10-19 — FTS5 tables and triggers are hand-written SQL migrations. — Drizzle does not model virtual tables.
- 2026-10-19 — Keep Electron Forge + Vite; fall back to electron-vite + electron-builder only if `better-sqlite3` packaging can't be made reliable. — Spec says Forge; native module setup is the known risk.
- 2026-10-19 — v1 reordered: manual projects, pause/resume and HUD grid before scanner, Git and launcher. — Delivers the core value early and keeps non-coders first-class.
- 2026-10-19 — "Never remove existing functions" narrowed to bug fixes. — Literal reading would accumulate dead code.
- 2026-10-19 — Build a prototype before v1 (plan in docs/prototype-plan.md). — User wants to try the core idea before the full build.
- 2026-10-19 — Prototype stores data in one JSON file behind a repository interface; SQLite comes in v1. — Avoids the better-sqlite3 native build setup while the UX is still being tested; the interface keeps the swap contained.
- 2026-10-19 — Prototype keeps the working name "Project HUD"; "Keepfire" is the leading candidate. — Rename is a small change once the name is confirmed.
- 2026-10-19 — Adopted the "Workshop" vision (Ignite, the Lab, Parts Bin, Marks, Snap, Rewind, Universe, voice, Copilot, Gesture Mode), phased in docs/vision.md. — User wants a futuristic, sci-fi-lab experience for any kind of project, software or hardware.
- 2026-10-19 — Prototype gains Ignite, the Lab canvas and a per-project Parts Bin; the Lab replaces the planned Project Detail view. — Creating projects and adding any kind of resource is the heart of the new vision.
- 2026-10-19 — The Lab canvas uses React Flow (MIT). — Pan, zoom, objects and lines out of the box; tldraw is source-available and not allowed.
- 2026-10-19 — Exploded View and tree layouts use d3-hierarchy (ISC), not elkjs. — elkjs is EPL-2.0, outside the permissive-licence rule.
- 2026-10-19 — Copilot will run on node-llama-cpp inside the app instead of requiring Ollama; local AI moves from v3 to v2. — Ollama is a separate install most people won't do, and AI drafting is central to Ignite.
- 2026-10-19 — Files up to 200 MB dropped into a Lab are copied into the media folder; bigger files are linked in place. — Keeps resources safe when originals move, without filling the disk with videos and CAD files.
- 2026-10-19 — Resource activity events merged into one `resource_added` event with the type in the payload. — Otherwise every Lab object type needs its own event name.
- 2026-10-19 — The sci-fi look is our own: no Marvel / Iron Man names, logos, sounds or look-alike assets; the assistant gets its own name. — The app may be sold, and movie names and art are trademarked.
- 2026-10-19 — UI sounds are generated with the Web Audio API. — No sound files to license.
- 2026-10-19 — The prototype follows the user's rewritten docs/prototype-plan.md (HUD grid, projects, archive, pause/resume, detail, developer extras). Ignite, the Lab and the Parts Bin stay in docs/vision.md for later phases. — The user rewrote the plan and set the current phase; it supersedes the two Workshop-prototype lines above.
- 2026-10-19 — Look changed to "hologram blue": electric blue on deep navy, Orbitron for headings, Rajdhani for HUD labels, cut-corner frames. — User's choice; the first look didn't match what they imagined.
- 2026-10-19 — Orbitron and Rajdhani are bundled via @fontsource (fonts SIL OFL-1.1, package code MIT). — OFL isn't on the MIT/Apache/BSD/ISC list, but it is the standard font licence and allows bundling in commercial apps (only selling the font files on their own is barred). Flagged to the user.
- 2026-10-20 — Part prices are stored as integer hundredths of the currency (`unitCostMinor`), for every currency, and shown via Intl.NumberFormat. — Never floats; one rule is simpler than per-currency minor units (Intl hides decimals for currencies like JPY).
- 2026-10-20 — Lab files up to 200 MB are copied into `media/<projectId>/`; bigger ones are linked in place. Images are served through a `hud-media://entry/<id>` protocol that only resolves files belonging to a Lab entry. — Keeps resources safe when originals move, without exposing the filesystem to the renderer.
- 2026-10-19 — No git for now; the local repo created earlier was removed. — User's instruction. When git comes back, commits carry no AI attribution.
- 2026-10-20 — The app is named Stokebay (stoke = keep a fire going + bay = a workshop bay). On first launch it copies data from the old "Project HUD" folder; the old folder is left as a backup. — The user chose it; the name, GitHub, stokebay.app and the web were checked and free.
- 2026-10-20 — Folder backups: daily copy of the data file (30 days) plus an add-only mirror of Lab files into a user-chosen folder such as Google Drive; restore keeps the current file aside and restarts. — Protects against losing the Mac without accounts, servers or cost; the user's cloud app does the uploading.
- 2026-10-20 — Settings gains Worlds (rename, recolour, delete — projects keep existing), Editor choice (VS Code, Cursor, Zed, Windsurf, Sublime Text; each with an `open -a` fallback on macOS) and a Show-data-folder button. — Onboarding promised worlds could be changed later; the user may not use VS Code.
- 2026-10-20 — Universe view added (shown as "Map"): projects as dots around you, one slice per world, distance = time since last activity. — Shows at a glance what's warm and what's drifting, without opening each card.
- 2026-10-20 — Replaced the "hologram blue" HUD look with a calm native macOS look: system font, sidebar layout, warm neutrals with one ember accent, light and dark mode following the system, hidden title bar with inset traffic lights. Orbitron/Rajdhani fonts removed. — User found the HUD style looked AI-generated and wanted a fresh, human-made product feel.
- 2026-10-20 — Status colours: active = ember (the accent), paused = cool blue, done = green, idea = violet. — Fits the "stoke the fire" idea: active projects are lit, paused ones have cooled.
- 2026-10-20 — User-facing jargon dropped: "Ignite" → "New project", "Universe" → "Map". Internal names (Ignite.tsx, view 'universe') kept to avoid churn.
- 2026-10-20 — Released as open source under AGPL-3.0-or-later, with a README and screenshots taken from the built-in sample projects (never real user data). — User chose open source so anyone can use it; AGPL keeps changed versions open, and as sole author the user can still license it differently later.
- 2026-10-20 — Prototype phase ended; v1 started with the database. — User said "next" to the proposed database and search step.
- 2026-10-20 — SQLite through Node's built-in `node:sqlite` instead of better-sqlite3 + Drizzle. — It ships inside Electron, so there is no native module to rebuild and tests run the same engine as the app; it has WAL, FTS5 and online backup. Drizzle has no driver for it, so migrations are hand-written numbered SQL steps tracked by `PRAGMA user_version`.
- 2026-10-20 — No foreign-key constraints; the store does cascading deletes itself. — Older data files can hold dangling ids (e.g. a deleted world's tag) and must still import.
- 2026-10-20 — On first start the existing projects.json is imported once and kept as projects.json.imported-<time>. — Upgrading must never lose or rewrite the user's only copy.
- 2026-10-20 — Backups (daily local and folder backups) stay JSON exports of the database; restore writes restore.json, applied on the next start. — The existing 30 days of Google Drive backups stay restorable, and the files stay readable without the app.
- 2026-10-20 — Search uses FTS5 external-content tables keyed on an integer `seq` column, prefix matching on every word. — Fast updates per edit and type-ahead without a second index; MiniSearch not needed (search ≈ 20–30 ms worst case at 50,000 notes).
- 2026-10-20 — Grid skips enter/exit animations above 60 cards and defers filtering while typing. — With 500 projects each keystroke cost ~330 ms; now 20–80 ms.
- 2026-10-20 — "Worlds" are called "Areas" in the app; data and code keep the `world` name. — "World" was sci-fi wording left from the old look; renaming only the copy keeps every user's data and backups as they are.
- 2026-10-20 — Picking an area opens an overview (counts, paused projects with their next step, projects going cold, the last week of activity) above its cards. — As a plain filter, areas did almost nothing with a handful of projects; the overview makes them answer "what's going on in this part of my life?".
- 2026-10-20 — "Find code projects" searches the whole home folder for Git repos as soon as it opens (48 folders read at once, max depth 8, skipping Library, Applications, media folders, app bundles, node_modules and similar; capped at 300,000 folders / 30 s). Results are sorted by when Git last recorded work (mtime of .git/logs/HEAD) and none are pre-selected. Picking a folder remains as "Choose a folder instead". — The user wanted no folder picking; on this Mac it finds 41 repos in under 0.4 s. Skipping ~/Library also keeps cloud-drive folders from being downloaded.
- 2026-10-20 — Fix: the old-name ("Project HUD") data copy now also skips folders that have a database. — After projects.json was moved into the database, the copy ran again on the next launch (no data lost: it only adds files and the database was untouched; the stray file was renamed).
- 2026-10-20 — macOS builds are ad-hoc signed inside-out, with a designated requirement of just the bundle id (app.stokebay.desktop), in a Forge postPackage hook. — The default ad-hoc identity changed with every build, so macOS silently dropped privacy permissions (e.g. Google Drive folder access) after each update and backups failed with EPERM. A paid Developer ID would replace this later. Settings now detects a blocked backup folder and links to Privacy settings.
- 2026-10-20 — The computer search covers the home folder, own folders at the top of the disk, /Users/Shared and connected drives (not system folders, Recovery, Time Machine). Top folders macOS blocks are reported with a link to Privacy settings, never skipped silently. — The installed app found 10 of 41 projects because macOS was quietly blocking Desktop/Documents/Downloads, and projects outside the home folder were never searched.
- 2026-10-20 — Weekly review asks about active projects from two weeks untouched ('dim' or 'cold' glow), ideas from 30 days, and paused projects only when paused and quiet for 30+ days with no reminder still ahead. — Asking before a project is fully cold is when a decision still helps (auto-pause takes active projects out at 30 days), ideas are allowed to sit longer, and a future reminder means the user already chose when to come back.
- 2026-10-20 — "Keep going" in the review is a `project_reviewed` event, so it counts as activity; for a paused project the same choice reads "Keep paused" and stays paused. — The event alone resets the clock without inventing a status change, and the project isn't asked about again until it goes quiet again.
- 2026-10-20 — The review's project list is fixed when it starts, "Finish now" ends it early (it still counts as this week's review), and the grid banner's "Not now" lasts until the app restarts. — Decisions change the live list mid-review; a review that's cut short is still a review; a dismissal that lasted forever would make the feature invisible.
- 2026-10-20 — Live Git tracking watches only `.git/HEAD` and `.git/logs/HEAD` of each plain repo (chokidar, 2 s debounce, at most 500 repos, most recently committed first); worktrees, submodules and anything past the cap rely on a background refresh every 10 minutes. — Those two files change on every commit, checkout, pull and reset, so watching them costs a few handles per repo instead of watching whole working trees.
- 2026-10-20 — A forced Git refresh that arrives while another is running now gets its own follow-up run instead of sharing the running one. — A commit noticed mid-run would otherwise be lost until the next focus or periodic refresh.
- 2026-10-20 — New commits are recorded as one `commit_detected` event per refresh, dated by the newest commit (capped at now), counted with `git rev-list --max-age`; nothing is recorded on the first read of a repo or when the last commit moves backwards. — Importing a repo isn't new work, and switching to an older branch isn't either.
- 2026-10-20 — Auto-pause ("Going cold", default 30 days) runs after the first Git refresh at startup, every 6 hours and when the setting changes; it leaves sample projects alone and writes why (plus the last commit) as "where I stopped". — Commit dates must be known first or busy repos would pause; the samples exist to show every state, including a project going cold.
- 2026-10-20 — Pausing reads the Git state in main (branch, last commit, `git --no-optional-locks status --porcelain -z`, 5 s timeout, at most 20 file names plus a full count) and stores it with the pause; the dialog pre-fills "Where I stopped" from the same read only while the field is untouched. — The renderer is never trusted for it, a background read must not block the user's own git commands, and a Git failure only means no context, never a failed pause.
- 2026-10-20 — "Remind me" times are 9:00 local on the chosen day (tomorrow … in 30 days). Main checks at startup and every 5 minutes and clears each reminder in the same save before the notification shows; reminders of resumed or archived projects are dropped silently. — Each reminder fires exactly once, even after a crash, and a morning nudge is calmer than one at the minute of pausing.
- 2026-10-20 — Pick up resumes first, then opens links (if on), the terminal (if on) and the editor last; anything that fails is listed in one toast and the project stays resumed. Terminal: Terminal.app on macOS, Windows Terminal then Command Prompt on Windows, x-terminal-emulator → gnome-terminal → konsole on Linux. — The editor is the window most likely in front, and a missing terminal shouldn't undo the resume.
- 2026-10-20 — A reminder clicked while no window is open creates one and keeps the project id in main; the new page asks for it once (`projects:takePendingFocus`) after subscribing. — Replaces a fixed 600 ms delay after `did-finish-load`, which raced the React effect that subscribes.
- 2026-10-20 — Quick capture is one hidden 560×208 window, made on the first shortcut press and reused; on macOS it's a `panel` window, centred on the display under the pointer a little above the middle. It loads the same renderer page with `#capture`, so no second Vite entry. — A panel takes the keyboard without bringing the main window forward and hands focus back to the app the user was in, like Spotlight; reusing the window makes later presses instant.
- 2026-10-20 — Text typed in quick capture is kept when the window is clicked away (blur) and cleared only after saving or Esc; the project resets to the last one captured to (else the most recently active) each time it opens. — Losing a half-written thought to a stray click defeats the point of capturing it.
- 2026-10-20 — Capture notes have no title and their `note_added` event carries `source: 'capture'`; a capture shortcut another app owns is reported in Settings (`capture:status`) rather than failing silently. Closing the main window in development (and on Windows/Linux) quits from the window's own `closed` handler. — The hidden capture window stops `window-all-closed` from firing, and `activate` now checks for the main window instead of counting windows.
- 2026-10-20 — The built-in terminal uses node-pty (MIT) for real shells and xterm.js (MIT) to draw them; it's the default for "Terminal" and Pick up, with Terminal, iTerm, Warp, Ghostty, kitty, Alacritty and WezTerm as alternatives in Settings. — A panel next to the project keeps people in one place; node-pty 1.1 ships N-API prebuilds, so nothing is compiled and the same binary loads in Electron and in tests.
- 2026-10-20 — node-pty stays out of the Vite bundle and is copied (lib + this platform's prebuild) into the app at package time, unpacked from the asar; `postinstall` and the package hook restore `spawn-helper`'s executable bit. — It loads a native binary and runs a helper from its own folder; npm drops the helper's executable bit, which makes every shell fail with "posix_spawnp failed".
- 2026-10-20 — Terminals start the user's own shell as a login shell in the project folder, with TERM=xterm-256color and a UTF-8 locale filled in when missing; output is batched every 8 ms, typing goes over one-way IPC messages, and nothing typed or printed is logged. Shells close with their window. — Finder-launched apps get a bare environment (no PATH additions, no locale), which breaks prompts and tools.
- 2026-10-20 — Releases are built by GitHub Actions on a version tag (`v*`), on real macOS, Windows and Linux machines, into a draft release that is published by hand; the same workflow runs by hand for test builds without a release. One Apple silicon machine builds both Mac versions. — Each platform's installers need that platform's tools (hdiutil, Squirrel, dpkg/rpm), and a draft keeps a bad build from reaching anyone.
- 2026-10-20 — Forge's native-module rebuild is off (`onlyModules: []`): node-pty is N-API, uses its ready-built binaries on macOS and Windows, and is compiled by `npm ci` on Linux, which has none. — Rebuilding it for the other Mac architecture fails, and N-API binaries never need rebuilding for Electron.
- 2026-10-20 — The Windows icon (`assets/icon.ico`) is made by `npm run icon` from the same render, as PNG entries at 16–256 px. — Every Windows since Vista reads PNG icons, so no extra image tool is needed.
